## Phase 1 — Schema + server foundations (one PR)

- **P1.1 Migration** (+ regenerate `database.ts` types + TECH_SPEC §2/§4 updates):
  - Add `audio` to the `memories.memory_type` check constraint **and add a fourth branch to `memories_type_invariants`** — edit the **current** definition in `supabase/migrations/20260801170000_paid_subscription_sol_hardening.sql:238-250` (the constraint was rewritten there; the original `20260525143000_memory_types.sql` version is superseded — P0.1 audit finding). It's a closed OR over exactly three types; without a new branch every `audio` insert fails 23514 regardless of the enum change. The `audio` branch: `content` **nullable AND permitted non-null** (description optional; old builds' edit screens write captions onto audio rows — a content-forbidding arm would turn those saves into raw Postgres errors), `illustration_status = 'none'`, `media_key`/`media_content_type` per the mirroring decision (default: mirror the clip, so non-null — settle in this PR).
  - **Widen the `memory_media.content_type` CHECK constraint** (`20260603120000_multi_asset_media_memories.sql:8-15` — currently enumerates image/video MIME types only; the audio row insert fails without this) to include the observed audio MIME types from P0.2.
  - Add `memories.audio_transcript` `text` nullable (invisible, search-only).
  - **Reuse the existing `memory_media.duration_ms`** column (`20260603120000_multi_asset_media_memories.sql:17` — already present and populated for videos; no new column).
  - Conditional trigger — **at-most-one, not exactly-one**: "exactly one `memory_media` row" is unenforceable at the `memories` table (insert order is memories row → tags → `replace_memory_media_assets`, so every audio memory transiently has zero media rows — the same transient `media` already accepts, and why the realtime retry gate exists). Enforce on `memory_media` writes instead: at most one row per `audio` parent, audio content types only under `audio` parents, and no audio content types under non-audio parents (mirror the child-table upper-bound pattern of the 6-tag cap trigger, `20260714120000_unlimited_memory_tags.sql`).
  - **Type immutability for `audio`:** no generic type-transition triggers exist today — the only app-level guard is `updateMemory`'s media-specific check (`src/services/memories.ts:~1157`), which says nothing about `audio`. Add a DB trigger (or extend the constraint strategy) forbidding `audio` ↔ other-type transitions, plus the matching `updateMemory` guard in Phase 2.
  - GIN index for transcript search: `to_tsvector('english', audio_transcript)`.
- **P1.2 `process-voice-memory` family mode:** extend the cleanup call's JSON response to `{ cleanedText, description, mentionedMemberIds }` — one provider call serves both fork branches. No new ledger operation (`transcription` + `voice_cleanup` unchanged); no change to onboarding mode (no description there, and the fork does not exist pre-auth). `description` is ≤ ~120 chars, empty string when speech is unusable — never an error, never garbled babble.
- **P1.3 Upload allow-list + storage-key patterns (all four):** add observed audio MIME types (from P0.2) to `get-upload-url` and `upload-media`, and widen **all four** extension allow-lists in `supabase/functions/_shared/storage-keys.ts`: `MEMORY_MEDIA_EXTENSION_PATTERN` (:14), `MEMORY_MEDIA_ASSET_EXTENSION_PATTERN` (:19), **and `MEMORY_MEDIA_FULL_PATTERN` / `MEMORY_MEDIA_ASSET_FULL_PATTERN` (:244-247)** — the FULL patterns feed `parseStorageKey`, which `_shared/family-access.ts` uses to resolve a key's owning family for authorization; missing them makes an uploaded clip **unplayable** (`get-media-url` fails closed), not just unuploadable. Add a `parseStorageKey('.../{assetId}.m4a')` regression test. Keep the backfill scripts' key derivation in sync per the existing cross-reference comment. Server-side size cap for a 2-minute AAC clip (~4 MB ceiling, generous).
- **P1.3b Looking Back eligibility exclusion (migration, same PR):** eligibility is **inclusion-by-default SQL**, not client filtering — `get_or_create_looking_back_packages` (`supabase/migrations/20260812120000_looking_back_themed_recipes.sql`, the `m.memory_type <> 'media' or exists(...)` predicate appears **twice**, ~:199 and ~:227) passes every non-media type unconditionally. Test must assert against the SQL RPC output, not just client behavior.

## Phase 2 — Capture flow: the fork (client PR)

- **P2.1 `useVoiceInput` restructure:** on stop, retain the local recording file (do not delete until a branch resolves) and kick `processVoiceMemory` immediately. Expose `{ status, transcriptResult, localUri, durationMs }`. Discard file on: turn-into-text chosen, modal dismissed/cancelled, or recording error. **Note: no file-cleanup pattern exists to extend** — the repo's only `FileSystem.deleteAsync` call sites are unrelated (share-card temp, export download); today's dictation flow never deletes the recorder's temp file and has no `AppState` handling. Build deletion on every exit path from scratch, and decide the post-enqueue orphan case explicitly: composer closed → clip queued → app killed leaves a local child-voice recording on disk with no queue entry to clean it (the pending queue is in-memory-only and never deletes local `fileUri`s, even on failure). Either add a startup sweep of the recording temp directory or record it as an accepted-risk note parallel to the queue's existing force-quit tradeoff — but decide, don't inherit silently. This is a PII surface, not just hygiene.
- **P2.2 Fork UI in `voice-speak-it-modal.tsx`:** recording-stopped state shows two equal-weight buttons — **"Turn into text"** / **"Keep the sound"** — plus a compact clip chip (duration). Neither branch waits on transcription visibly (it started at stop; by selection time it's resolved or near-resolved — show the existing processing state only if genuinely still in flight). Turn-into-text = today's behavior + file deletion (audio chip visibly disappears). Keep-the-sound hands `{ localUri, durationMs, description?, transcript?, mentionedMemberIds? }` to the composer and closes the modal.
  - **Keep-the-sound must never depend on transcription success.** The clip is the artifact; the server call only supplies optional metadata. On transcription failure (offline, OpenAI 5xx): keep proceeds with empty description/transcript and no auto-tags — never an error state, never a discarded clip (failing scenario that must have a test: baby's laugh recorded on the subway, network down, memory still saves). If the in-flight call resolves *after* the memory saves, patch the description/transcript in fire-and-forget (the design doc's backfill behavior — mirror the emotion-backfill pattern); if it never resolves, the memory simply stays description-less and editable. Only **turn-into-text** requires the transcript and may surface today's error state.
  - **User text always beats the AI caption — in both windows (decided 2026-08-17).** In-composer: the AI description prefills only a still-empty field; if the user has typed anything by the time the result arrives, the suggestion is discarded (never replace/merge/prompt — same empty-form-only spirit as draft restore). Post-save: the description backfill must be a **conditional empty-only write** (`... where content is null or content = ''`-style guard, enforced at the DB write, not a client-side check), so a user who saves and immediately types their own caption in edit can never be clobbered by the in-flight patch — the backfill silently no-ops. Asymmetry: the invisible `audio_transcript` is not user-editable, so its backfill is unconditional and independent of the description guard. Tests: user-typed-then-AI-arrives (composer), user-edits-then-backfill-lands (post-save race, asserting the conditional write shape).
  - **Fork is composer-only — the modal has a second consumer:** `voice-speak-it-modal.tsx` is also mounted by `app/(app)/memory/[id]/edit.tsx` (dictation into an existing memory). An ungated fork there would offer "Keep the sound" mid-edit, contradicting type immutability. Add a modal mode prop (fork only in the new-memory context) + a test that edit-screen dictation shows no fork.
  - **Clip file custody:** at keep-the-sound time, copy the clip out of the recorder's temp location into an app-owned recordings directory (a later `prepareToRecordAsync` in the same composer session, or an OS cache purge before a deferred retry, can invalidate the temp URI). This directory is also what P2.1's startup sweep cleans.
  - **Fork additions from the design handoff (adopted 2026-08-19):** a quiet tertiary **"Record again"** on the fork sheet (discards the current clip + transcript, restarts recording); a **terminal transcription-failure state** — turn-into-text shows an error treatment (may gracefully suggest keeping the sound instead) while keep-the-sound stays fully available; and an explicit **2:00 auto-stop treatment** in the recorder (the cap moment, not just a counting timer — design still owes this artboard).
- **P2.3 Composer (`new-memory.tsx`):** audio attachment present → emergent `audio` type: media picker and AI toggle hidden; clip chip (play/pause preview + duration + remove); description into the content field with prefill (empty → placeholder "Add a note about this sound"); `mentionedMemberIds` pre-tag via the existing auto-tag hook path; date picker + tag picker unchanged.
  - **Clip removal = Undo, not a type flip (adopted from design handoff 2026-08-19, supersedes the earlier "revert to text composer"):** removing the clip shows an Undo affordance and **disables Save** while the clip is gone; Undo restores it. No surprise conversion to a text memory mid-compose. Cancel/dismiss with the clip removed discards per P2.1's custody rules.
  - **In-composer re-record (adopted):** the composer toolbar mic re-records, replacing the current clip pre-save, with the hint "Recording again replaces this sound."
- **P2.4 Posting — a parameterized fork of the media path, not a drop-in "extend":** `createMediaMemory` hardcodes `memory_type: 'media'` in the insert (`src/services/memories.ts:~1094`), in `resolveMediaMemoryInsertConflict`'s repair check (`~1039` — an audio retry-conflict would silently give up), and in `validateMemoryContent(input.content, 'media')` (`~1064`). Either add `createAudioMemory` sharing the upload/rollback internals, or parameterize those three sites explicitly. Flow: upload clip via `upload-media` → insert `memories` row (`memory_type: 'audio'`, `content` = description, `audio_transcript`) + one `memory_media` row (existing `duration_ms`, no preview key) → rollback deletes the uploaded clip on insert failure. `media_key`/`media_content_type` mirror the clip (default: mirror, consistent with `media`; settle with P1.1's invariant branch).
  - **The asset-transform pipeline will crash on a raw `.m4a` as-is:** `uploadMemoryMediaAssets`' inner `uploadAsset` (`src/services/memory-posting.ts`) gates the EXIF strip on `isVideoContentType` — anything non-video, including audio, falls into `stripImageMetadataForUpload` → `ImageManipulator.manipulateAsync` on the clip file (native image-decode throw, unguarded), and `getMediaExtensionFromContentType` (`src/utils/media-validation.ts`) has no audio case ("Unsupported file type"). Add an explicit audio branch: skip compression, skip EXIF strip, skip preview generation, add audio extensions to the content-type→extension map — or give audio its own minimal upload helper that shares only presign/PUT/rollback. Decide which in-PR; do not let audio flow through the image branch.
  - **Emotion-kick gate must become type-aware:** the queue's post-success gate uses `hasImageMediaAsset` (`src/services/memory-posting.ts:~98`, consumed at `src/hooks/use-pending-memory-uploads.tsx:~130`), which treats anything non-video — including `audio/mp4` — as an image and would fire the **photo/vision** emotion path, which the server then rejects (`invalid_memory_type`). Route audio to the text-classifier kick instead.
  - **`updateMemory` guard:** extend the type-immutability check (`src/services/memories.ts:~1157`) so `audio` can never be converted to/from another type (pairs with the P1.1 DB trigger).
- **P2.5 Draft autosave:** clip never persisted in the draft (same rule + rationale as media attachments); text/tags/date survive.
- **P2.6 Analytics:** typed events — fork shown, fork choice (`text` | `audio`), audio memory saved (duration bucket, has-description). Follow analytics.md conventions; no content/transcript in properties.
- **P2.7 Tests:** fork state machine unit tests (file retention/discard on every exit path); modal component tests; posting-queue integration (upload → insert → rollback); composer screen test (emergent type, prefill, pre-tag, draft exclusion); analytics event assertions.

## Risks

| Risk | Mitigation |
|------|------------|
| Old installed clients render unknown `memory_type` wrong | P0.1 audit complete: no crashes, but detail shows a permanent fake "generating" animation and timeline an empty box — three-file defensive patch via EAS Update saturates **before** the migration deploys |
| Gallery-import branch rewrites the composer/timeline files Phases 2–3 target | Decided: audio ships first on `main`; gallery import absorbs the rebase and must carry the audio composer/timeline surfaces forward (P0.4) |
| Keep-the-sound blocked by transcription failure (offline/5xx) destroys the one unrecoverable artifact | P2.2: keep proceeds with empty metadata; post-save fire-and-forget backfill; only turn-into-text requires the transcript |
| Recorded MIME differs per platform / rejected by allow-list | P0.2 empirical check on both platforms pins the list; server rejects unknowns loudly in dev |
| Audio session conflicts (recorder vs. player vs. timeline video) | P4.3 device matrix; single-active-player rule; pause audio on video autoplay |
| Description generation degrades dictation latency | Same single cleanup call — description adds tokens, not a round trip; assert response-time budget in Deno test fixture |
| Fork adds friction to heavy dictators | One tap, zero wait (transcription pre-started); analytics on fork choice validates; preference shortcut is ready backlog |
| Transcript PII in logs | Existing no-content-logging rules; review new code paths for accidental logging of `audio_transcript`/description |
| Orphaned child-voice recordings on device (app killed mid-fork or post-enqueue) | P2.1 builds deletion on every exit path + explicit decision on the post-enqueue orphan window (startup sweep vs. documented accepted risk) |
| Unreachable-tail installs never get the unknown-type fallback (OTA ceiling) | P4.4 telemetry-defined saturation gate + explicit accept-or-version-floor decision before enabling creation |
