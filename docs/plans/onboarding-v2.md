# Onboarding v2 — implementation plan

## Goal

Ship the owner-path onboarding redesign agreed on the Onboarding v2 design canvas (private artifact `HRdjkEWstVEjnrbJBSdnnW`, 2026-11-04) in the next store build (1.5.2), with an EAS Update to 1.5.x as a supplement: a tappable "sounds like you" opener that the next screen answers, a founders story that connects to it, a goal-led run from "what do you want to remember" into the first capture, a hold-to-seal promise before the reminder ask, a four-card "what's included" carousel, a richer paywall, a clearer photo step, honest portrait frames, and a "how did you find us" question at the very end whose answer lands in PostHog and the database. Done = the owner happy path runs end to end on device and in Maestro, funnel events still join across the old and new step names, and docs/tests are updated.

## Context

Current owner flow (docs/features/onboarding.md, `app/(onboarding)/*`), in route order:

`welcome` → `story?beat=0|1|2` (three passive recognition beats) → `founders` → `artifact` → `kids` → `family-name` → `bridge` → `capture` (modes `idle | recording | transcribing | compose`; compose is the typing/media state) → `aha` → `year` → `notifications` → `email` → `code` (OTP; `commitOnboarding` runs here, then `router.replace` to `included`, or `portrait` for complimentary access) → `included` → `trial` → `paywall` → `portrait` (photo pick → painting + `OnbBirthdayAsk`) → `reveal` (sibling chain; last reveal → `import-offer` when `isGalleryImportFeatureEnabled`, else timeline; "Later" → family roster) → `import-offer`.

Facts the plan relies on:

- **Draft**: `src/utils/onboarding-progress.ts` — `OnboardingDraft` (version 1, AsyncStorage key `momora.onboardingDraft`). `isOnboardingDraftShape` checks only core fields, so new optional fields don't need a version bump. `OnboardingStepId` is a closed union; `onboardingStepRoute()` in `src/lib/onboarding-routes.ts` is an exhaustive switch over it. It is only reached for a **signed-in user with zero memberships** (`resolvePostAuthDestination` in `src/lib/onboarding-routing.ts`, via `app/index.tsx`), i.e. in practice at `email`/`code`. A pre-auth cold launch always lands on `welcome` (`app/index.tsx` redirects when there's no session, and `welcome.tsx` patches `step: 'welcome'`), keeping leftover `kidNames`/`capture`. Draft persistence is a **hand-enumerated field list** in the debounced effect of `src/hooks/use-onboarding-flow.tsx` (`patchOnboardingDraft({ step, ownerUserId, kidNames, … })`); `patch()` alone only updates memory. `code.tsx`'s `finishAfterCommit` calls `clear()` before routing into the post-auth arc, so post-auth screens can't read the draft — name copy there goes through `useOnboardingKidPossessive` / `useFamilyMembers`.
- **Analytics**: `onboarding_step_viewed { step, flow }` fires from `app/(onboarding)/_layout.tsx` using `onboardingAnalyticsStepFromPathname()`; the step type is `OnboardingAnalyticsStep` in `src/services/analytics.ts` (`OnboardingStepId` + `reveal | paused | import-offer | join-*`). `supabase/scripts/eval-trial-funnel.ts` keys off `portrait`/`reveal` step names. `setPersonProperties()` exists with a closed `AnalyticsPersonProperties` interface.
- **Post-auth routes**: `POST_AUTH_ONBOARDING_PATHNAMES` in `src/lib/onboarding-routes.ts` decides which onboarding paths a signed-in member may stay on; the layout redirects anything else to root.
- **Capture → memory type** (`src/services/onboarding.ts`, first-memory commit): text-only capture → `text_illustration` with `deferIllustration: true` (painted after a kid portrait is ready, `startPendingOnboardingIllustration`); a capture with `mediaUri` → `media` memory, never illustrated. Onboarding voice is dictation (`processOnboardingVoiceMemory` returns `cleanedText`); audio is never persisted (CLAUDE.md voice rule).
- **Capture prompt**: `capturePrompt(names, selectedIndexes)` in `src/utils/onboarding-copy.ts` uses names only.
- **Owner decisions (2026-11-04)**: (1) show an optional "Add a photo" row on the idle/voice capture state — this reverses the 2026-07-31 decision recorded in `capture.tsx` (comment above the idle footer) and the onboarding doc changelog; (2) keep the year-film 10-memories-per-month minimum but still advertise monthly films; (3) advertise holiday cards; (4) artwork scanning is live; (5) keep "Maybe later" on the promise; (6) store "how did you find us" as a PostHog person property **and** a DB column; founders imagery stays illustrated.
- **Copy rule**: AGENTS.md → Coding standards → Product & marketing copy (name the thing; buttons name the action). VoC register in docs/features/onboarding.md "Copy register rules".
- **Deps available**: `react-native-reanimated` 4.3.1 and `react-native-gesture-handler` (hold-to-seal, auto-scroll, carousel) — no new native modules, so the code *can* ship by EAS Update. **But an OTA barely reaches new owners**: `app.json` `updates` has only a `url` (launch wait 0) and nothing imports `expo-updates`, so a fresh install's first session — where onboarding happens — runs the bundle embedded in the store binary; an OTA applies only on the next cold launch.
- **Assets**: `assets/onboarding/*.webp` holds the founder-family art used today (`src/constants/onboarding-memories.ts`, `onboarding-illustrations.ts`). The canvas used extra AI-generated photos, crayon stickers and two kid drawings that are not in the repo.

## Steps

### WP0 — Plumbing

WP0 repoints routes to screens WP1 creates, so WP0 + WP1 land in one commit (or `story` stays registered until WP1 merges).

1. **Step ids** (`src/utils/onboarding-progress.ts`): add `'sounds-like-you' | 'mirror' | 'remember' | 'promise'` to `OnboardingStepId`. Keep the legacy ids (`story-0|1|2`, `artifact`, `family-name`) in the union for resume of drafts written by the old build.
2. **Draft fields** (same file): add optional `painPoints?: PainPointId[]`, `rememberFocus?: RememberFocusId[]`, `promiseSealed?: boolean`. Export the id unions and their display data from a new `src/constants/onboarding-v2.ts` (pain-point label, mirror answer, thumbnail asset; remember-focus label, tile asset, prompt hint). Extend `isOnboardingDraftShape` to accept these as absent or arrays/booleans (a wrong-typed optional field is dropped, never the whole draft; unknown ids are filtered on read). **Add all three to the persisted field list in `src/hooks/use-onboarding-flow.tsx`** (or replace the list with the whole draft minus `version`), with a hook test proving a patched `painPoints` reaches `AsyncStorage.setItem`. These fields are pre-auth only; nothing after OTP may depend on them.
3. **Routes** (`src/lib/onboarding-routes.ts`): add route constants for `sounds-like-you`, `mirror`, `remember`, `promise`, `attribution`. Update `onboardingStepRoute()`: new ids → new screens; legacy `story-0|1|2` → `sounds-like-you`; `artifact` → `founders`; `family-name` → `kids`. Add `/attribution` to `POST_AUTH_ONBOARDING_PATHNAMES`. Update `onboardingAnalyticsStepFromPathname()` for the new paths. Replace `onboardingStoryRoute()` with an `onboardingSoundsLikeYouRoute` constant and repoint every caller: `welcome.tsx`, `app/(auth)/login.tsx` ("Create an account" link) and `src/screen-tests/reviewer-password.integration.test.tsx`; `founders.tsx` (imports `onboardingArtifactRoute`) and `kids.tsx` (imports `onboardingFamilyNameRoute`) are repointed in steps 9–10. Remove `onboardingArtifactRoute`/`onboardingFamilyNameRoute` only after those edits. The four new pre-auth screens **do not write `draft.step`** (pre-auth always restarts at welcome, and a resume step only matters at `email`/`code`), so a v1 build after a rollback never reads a v2 step id. Still make `onboardingStepRoute()`'s `default` return `onboardingWelcomeRoute` instead of the `never` passthrough, so an unknown step id (e.g. a v2 draft read by a rolled-back build) can't produce `<Redirect href={undefined}>`.
4. **Analytics** (`src/services/analytics.ts`): add `'attribution'` to `OnboardingAnalyticsStep` (the new `OnboardingStepId`s flow in automatically). Add events: `onboarding_pains_selected { count: number; ids: string }` (comma-joined ids, no free text), `onboarding_promise { sealed: boolean }`, `onboarding_attribution { source: AcquisitionSource | 'skipped' }`. Add `acquisition_source?: AcquisitionSource` to `AnalyticsPersonProperties`. Register `onboarding_version: 'v2'` as a PostHog super property when `sounds-like-you` mounts (the owner path's start — not `welcome`, which joiners and log-ins also pass), so paywall, commit and trial events carry it too. Add a `setPersonPropertiesOnce()` wrapper in `src/services/analytics.ts` (the SDK's `$set_once` argument) and call it at commit, so the person keeps their first version. Accept that a rollback leaves the persisted super property on v1 events until the next v2 build. Add `onboarding_included_card_viewed { index: number }` for the pager. Also add it as a typed property of `onboarding_step_viewed` (extend the event type in `AnalyticsEventMap`; `onboardingAnalyticsStepFromPathname()` keeps returning `{step, flow}` and `_layout.tsx` spreads in the version), for both owner and joiner flows. Keep every new event scalar-only so `AssertEventsAreScalarOnly` still compiles.
5. **Layout** (`app/(onboarding)/_layout.tsx`): register the new `Stack.Screen`s; drop `story`, `artifact`, `family-name` registrations only after WP1/WP2 land (their files are deleted there).

## Risks & mitigations

- **Stale drafts after the update** — a pre-auth user restarts at `welcome` with an old-shape draft (kid names and maybe a capture, no v2 fields): every v2 screen must treat missing `painPoints`/`rememberFocus`/`promiseSealed` as normal (tests render each new screen from a v1-shaped draft). Legacy step ids only matter for signed-in, no-membership resumes; they stay in the union and map to v2 successors (step 3).
- **Rollback** — the store build can't be rolled back by OTA; an OTA republish only reverts the 1.5.x supplement. New pre-auth screens never write `step` (step 3), so a v1 bundle can't read a v2 step id. The DB columns are additive and harmless to v1.
- **Promise/quiz vs VoC** — owner-approved exception to anti-requirements #1–#2; watch the guardrails in step 34.
- **Attribution has no denominator** — only trial starters answer, so it shows where converters came from, not channel conversion rates.
- **Funnel discontinuity** — `story-*`, `artifact` and `family-name` stop firing and new names appear, so the 2026-08-12 baseline and dashboards break at the cut-over. Mitigation: `onboarding_version` property; unchanged screens keep their names; document the old→new mapping (story-0→sounds-like-you, artifact→founders, family-name→kids) in the analytics doc.
- **Photo row lowers illustrated first pages** — media captures never get illustrated, so more parents may miss the illustration delight. Mitigation: copy states the trade-off ("instead of an illustration"); track `onboarding_capture_completed.has_media` share before/after.
- **Hold-to-seal accessibility** — long-press is hard for some users and screen readers. Mitigation: accessible "Seal it" button + "Maybe later".
- **Motion** (mirror auto-scroll, carousel auto-advance, paywall strip) — reduce-motion fallbacks for each.
- **Attribution write failures** — never block navigation; failed writes log a code only (no PII).
- **Attribution coverage** — app kills after purchase skip the question; accepted. Users who never start a trial are never asked (out of scope).
- **Advertised features with conditions** (monthly film needs 10 memories/month; holiday cards US/CA; book printing paid) — owner chose to advertise them plainly; keep claims factual (no "free", no "every month guaranteed" wording beyond what the canvas shows).

## Out of scope

- Join path (J1–J5), returning-user routing, `code.tsx` commit logic, billing/paywall purchase logic, portrait generation pipeline, illustration of photo memories, lowering the monthly-film threshold, Sign in with Apple/Google, new paywall pricing tests, attribution for users who never start a trial.
